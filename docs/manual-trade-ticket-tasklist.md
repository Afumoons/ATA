# Manual Trade Ticket Tasklist

_Last updated: 2026-04-30 (T0 specification documented)_

## Goal
Build an operator-side manual trade ticket in the UI that supports risk-based sizing, market/pending entries, SL/TP calculation, and explicit tagging that the trade is manual by user, not generated by the autonomous strategy engine.

---

## Scope Principles
- Manual user trade flow must be clearly separated from autonomous strategy execution.
- Manual trades must not contaminate strategy attribution, specialist evaluation, drift logic, or research/live stats.
- Roll out in stages: calculator first, preview second, live submit third.
- Keep all live execution changes guarded, explicit, and audit-friendly.

## Definition of Done
- Operator can open the UI ticket and calculate risk-based lot sizing accurately.
- Operator can choose market/pending, buy/sell, risk mode, and SL/TP mode.
- Manual trades are explicitly tagged and remain fully segregated from autonomous strategy stats.
- Live submit is guarded with confirmation and audit logging.
- Execution/audit UI can distinguish manual user trades from autonomous system trades.
